# PilotLauncher: устройство и ограничения

Версия 1.4.2. Раздел «Не проверено» перечисляет то, что не проверялось на живом ПК.

## Назначение

Лаунчер версий Pilot в духе TLauncher: выбрать редакцию и версию, нажать «Запустить». Версии ICE Enterprise, ICE, BIM, ECM и myAdmin скачиваются из центра загрузок <https://pilot.ascon.ru/release/> и запускаются одновременно, не мешая друг другу.

## Возможности

- Скачивание и запуск нескольких версий одновременно: у каждой свои настройки, логины и кэш.
- Версия, установленная в системе, определяется и предлагается как готовая; можно поставить её копию для отдельного пользователя.
- Скачанные установщики удаляются сразу после распаковки.
- Работа без интернета: установщики добавляются из файлов, можно указать папку с установщиками и сохранять zip версии для переноса на ПК без сети.
- В заголовке окна запущенного клиента видна версия.
- Заметки о выпуске с <https://help.pilotems.com/ru/Content/RelNotes.htm> для выбранной версии и изменения между двумя версиями.
- Режим «Предварительные версии» (в настройках): в списке появляются сборки из <https://pilot.ascon.ru/beta/> с пометкой «бета», заметки берутся с бета-страницы.
- Избранные версии: кнопка-звезда рядом с выбором версии.
- Расширения PilotLookUp и DynamoPilot для конкретной версии: установка, обновление, удаление, одна общая копия на все версии.
- Установка выбранной версии в систему с заменой текущей.
- Поставка в виде установщика и портативной версии.
- Проверка обновлений лаунчера при запуске (отключается в настройках) и обновление одной кнопкой.

## Не входит в лаунчер

- Серверные пакеты Pilot, подключения к базам, управление базами.
- Изменения уже установленного Pilot, кроме явных команд «Установить в систему (заменить текущую)» и «Удалить из системы».
- Обновление без участия пользователя (лаунчер только предлагает), ПК без прав администратора, не-Windows.
- Очистка кэша и показ размера профиля версии (нужен доступ к чужому профилю).

## Окно

Внизу выбор редакции и версии и большая кнопка «Запустить» со стрелкой-меню: удалить копию, удалить из системы, открыть папку, ярлык, поставить для отдельного пользователя. При удалении копии лаунчер спрашивает, удалять ли данные версии; слово «пользователь» в тексте не используется. Версии не привязаны к стендам или проектам.

Размер окна: при первом запуске 1100 на 780 (было 860 на 540), но не больше рабочей области экрана и не меньше 700 на 470. При закрытии окна (и при сворачивании в трей, пока работают клиенты) размер записывается в `settings.json` (`WindowWidth`, `WindowHeight`, `WindowMaximized`), при следующем запуске окно открывается с ним (`WindowSizing.Choose`). Развёрнутое окно запоминается развёрнутым, а размер для возврата берётся из `RestoreBounds`. Сохранённый размер больше экрана (например, записан на другом мониторе), нулевой, отрицательный или записанный только наполовину не используется или подрезается. Положение окна не запоминается: окно открывается по центру. Выход через «Выход» в трее без закрытия окна размер не записывает (он записан при сворачивании в трей).

## Технологии

WPF, .NET 10, тема Fluent по настройке Windows. Один самодостаточный exe, .NET на ПК не нужен.

## Изоляция версий

Каждая версия запускается под отдельным локальным пользователем Windows. Подмена `APPDATA` для этого не подходит: часть путей клиент берёт из профиля через API Windows.

- Имя пользователя: `pl` + 4 символа хэша SID владельца + код редакции + `<мажор>x<минор>x<сборка>`, не длиннее 20 символов. Хэш владельца нужен, чтобы два пользователя Windows на одном ПК не сбрасывали пароли друг друга.
- Пароль случайный, 32 символа, хранится через DPAPI для текущего пользователя Windows.
- Пользователи скрываются с экрана входа записью в `HKLM\...\Winlogon\SpecialAccounts\UserList`.
- Папка версий по умолчанию `%ProgramData%\PilotLauncher\versions`: у остальных пользователей там чтение и запуск, но не изменение чужих файлов (стандартные права ProgramData), отдельный ACL не нужен.
- Повышение прав через `runas` для той же программы с ключом `--admin`; права администратора нужны только для создания и удаления пользователя. Помощник работает только с учётными записями своего формата (`^pl[0-9a-f]{4}[EIBC]...`).
- Установка лаунчера для одного пользователя: копия exe, ярлык «Пуск», запись в «Приложения». Установщик это тот же exe, у которого имя оканчивается на `-Setup`.

## Данные Pilot копии (журналы, настройки)

- Проблема: профиль изолированного пользователя закрыт для основного, а кнопка «открыть журнал» в Pilot копии (`Process.Start` с `UseShellExecute` на папку) заканчивается «Отказано в доступе». Воспроизведено под изолированным пользователем: так же не открывается никакая папка, даже `C:\Users\Public\Documents`, то есть дело не в правах на папку журнала, а в том, что оболочка передаёт открытие проводнику другого пользователя, и Windows отказывает. Выдача прав на папку эту кнопку не чинит (проверено). Попытки обойти настройками проводника в профиле копии (режим «отдельный процесс», свой глагол `open` для папок, отключённый делегат) окна не дали, откатаны, способа починить саму кнопку нет.
- Что сделано: основной пользователь получает доступ к `AppData\Roaming\ASCON\<продукт>` профиля копии (там `Logs` и `Settings`), и в меню версии есть пункт «Открыть данные Pilot копии» (`MainViewModel.OpenData`), открывающий эту папку в проводнике основного пользователя. Сообщения: профиля ещё нет (копия не запускалась), папки ещё нет, нет доступа (тогда нужен запуск копии).
- Выдача доступа (`LaunchService.GrantOwnerAccessOnceAsync`, `ProfileAccessGranter`): один раз при первом запуске копии в отдельном профиле, сразу после подготовки пользователя (профиль Windows создаёт при первом входе пользователя, раньше папки нет, а создание пользователя уже спрашивает права, поэтому на «Добавить из файла» запросов не прибавляется). Короткий помощник `cmd.exe` запускается под самим изолированным пользователем (он владелец своего профиля и может менять права в нём; запроса Windows и прав администратора нет): `md %APPDATA%\ASCON\<продукт>` и `icacls ... /grant *<SID основного пользователя>:(OI)(CI)M`. В командную строку попадают только SID и имя папки продукта известного вида. Заметка `owner-access.txt` в папке версии (`<пользователь> <SID>`) говорит, что выдано; другой SID заметку недействительной делает. Сбой выдачи пишется в журнал и запуск не останавливает, при следующем запуске попытка повторяется. Права «изменение» (а не только чтение), чтобы можно было и чистить журналы.
- Что получает основной пользователь: только эту папку продукта в профиле копии, не весь профиль. Другие пользователи ПК ничего не получают.
- Проверено вживую на настоящем изолированном пользователе: помощник возвращает доступ к существующей папке и создаёт и открывает папку, которой не было; пункт меню открывает окно проводника на этой папке.

## Удаление копии

- Сначала удаляется папка версии, потом, если выбрана галочка, пользователь Windows и его профиль через повышенную копию (`delete-user`). Отсутствующая папка не ошибка: если прошлая попытка уже удалила её и упала позже, повтор доходит до пользователя.
- Запущенная копия. Раньше `Directory.Delete(recursive)` шёл по файлам, падал на первом занятом (при открытом Pilot это `Ascon.Pilot.AutomationScripts.dll`) с английским «Could not delete…» и оставлял разрушенную половину: `manifest.json` уже был удалён, поэтому версия пропадала из списка, а на диске лежали остатки, из-за которых повторная загрузка этой версии давала «уже есть в хранилище». Теперь перед удалением `VersionStore.FindFileInUse` пробует открыть каждый файл папки на запись (ничего не пишется): запущенная программа держит свои exe и библиотеки, и тогда открытие на запись даёт ошибку «файл занят» (код 32). Чтение и переименование папки при этом разрешены (проверено: папка запущенной программы переименовывается), поэтому проверка делается на самих файлах. Если что-то занято, `VersionInUseException`: «<редакция> <версия> нельзя удалить, пока она запущена. Закройте все окна Pilot этой версии (проверьте и значок в трее) и повторите. Ничего не удалено, версия осталась в списке.», ничего не изменено. Проверено в окне: при запущенной программе из папки копии сообщение, папка и версия на месте; после закрытия программы удаление проходит.
- Дальше папка не стирается на месте, а сначала переносится в `<хранилище>\.trash` (версия сразу пропадает из хранилища целиком, полуудалённая за неё выдана быть не может), там стирается; если сканер ещё держит файл, остаток убирается при следующем запуске.
- Остатки (`VersionStore.CleanLeftovers`, при каждом запуске лаунчера): всё в `.trash`; папки версий без `manifest.json` (версия кладётся в хранилище только целой, значит такая это остаток прерванного удаления); папки `*.partial` старше 12 часов (недоделанная установка). Установка версии поверх остатка (`EnsureAbsent`) убирает остаток, а целую версию не трогает («уже есть в хранилище»).
- Если шаг с пользователем не удался (профиль занят, окно запроса Windows отклонено), `VersionLibrary.DeleteStoredAsync` бросает `ProfileNotRemovedException`: копия уже удалена, окно сообщает «Копия удалена, но данные версии остались» с именем пользователя и причиной (код Windows из `DeleteProfile`), список версий обновляется в любом случае. Раньше при таком сбое список не обновлялся: удалённая копия оставалась в нём как «призрак», а повторное удаление падало на несуществующей папке с сообщением «закройте окна Pilot».
- Пароль пользователя при сбое остаётся в хранилище паролей, поэтому при повторной загрузке той же версии пользователь используется снова.
- Замечено на этом ПК: после удаления копии профиль пользователя `pl…E26x13x62219` остался загруженным в `HKEY_USERS` при отсутствии его процессов (после перезагрузки, последний запуск был за два дня до того), `DeleteProfile` завершился ошибкой. Что держит профиль, не установлено (без прав администратора это не видно); загружен и профиль пользователя от старой версии лаунчера.

## Общие папки

- Зачем: версия в отдельном профиле работает под другим пользователем Windows и не имеет доступа в профиль основного (так и должно быть). Файлы, которые нужно открыть в изолированном Pilot (загрузка модуля расширения и подобное), кладут в общую папку. Раздел в «Настройках» (`LauncherSettings.SharedFolders`, полные пути).
- Папка по умолчанию: `<Общие документы>\Pilot Launcher` (`SharedFolders.DefaultFolder`). В «Общих документах» группа «ИНТЕРАКТИВНЫЕ» уже имеет право изменения с наследованием, поэтому для неё ничего не выдаётся и повышение прав не нужно; кнопка создаёт её обычным `CreateDirectory`. Проверено вживую под изолированным пользователем: чтение, чтение и запись (как открывает файл Pilot), создание, правка и удаление файлов, правка файла основного пользователя, и основной видит изменения.
- Другая папка: чтобы открыть, нужны права администратора. Одно подтверждение Windows на все изменения списка (команда `apply-shares`, `SharedFolderService`/`SharedFolderAdmin`). Изолированные пользователи одного владельца (метка `pl<тег>…`) входят в локальную группу `PilotLauncher-<тег>`, группа получает на папку право изменения с наследованием (`FolderAcl`). Так учётная запись, созданная позже, получает доступ сразу: `ensure-user` добавляет её в группу, если группа уже есть. Группа на каждого пользователя Windows своя, чтобы один не открывал папки аккаунтам другого. «Убрать» снимает запись группы с папки, файлы не трогает; группу и её членов не удаляет.
- Что можно открыть, проверяет `SharedFolders.Validate` и в окне, и в повышенной копии (она аргументам не доверяет): путь полный и локальный (не сетевой, диск фиксированный), папка существует и путь к ней не проходит через ссылку (junction, символическую ссылку, короткое имя, подставленный диск), не диск целиком, не `ProgramData` целиком, не папка `C:\Users` и не папка профиля любого пользователя целиком (вложенные можно), не внутри Windows, Program Files, Program Files (x86), `%ProgramData%\PilotLauncher` (там лежат скачанные версии), `%LOCALAPPDATA%\PilotLauncher` любого пользователя ПК и папки данных лаунчера. Причина: право изменения на системной папке или на папке с версиями позволило бы изолированному пользователю менять систему или чужие версии. Повышенная копия принимает только свои команды: метка владельца из четырёх шестнадцатеричных знаков, пользователи только своего формата и владельца, всё проверяется до первого изменения (отказ по одной папке не меняет остальные). Папку данных лаунчера, которую нельзя открывать, повышенная копия определяет сама (`LauncherPaths`), а не берёт из аргументов.
- Ссылки выше по пути (исправлено в 1.4.1 после проверки безопасности): первая версия смотрела только, не является ли ссылкой последняя часть пути, и сравнивала текст пути с запрещёнными папками, поэтому `C:\Моя\Ссылка\System32` при ссылке на `C:\Windows` проходила, а права выдавались на настоящую системную папку. Теперь папка открывается один раз (`NativeFolder.Open`, `CreateFile` с `FILE_FLAG_BACKUP_SEMANTICS`), настоящий путь берётся у системы по дескриптору (`GetFinalPathNameByHandle`), и при любом отличии от введённого пути отказ. Права выдаются через тот же дескриптор (`SetEntriesInAcl` + `SetSecurityInfo`, система сама передаёт их содержимому, запрет наследования от родителя сохраняется как был), а проверка запрещённых папок выполняется ещё раз над настоящим путём именно этого открытого объекта, поэтому подмена папки ссылкой между проверкой и выдачей ничего не меняет.
- Ограничение: файл надо класть в общую папку без повышения прав. Файл, созданный процессом с правами администратора (копирование в чужую папку с запросом Windows), получает метку «Высокий обязательный уровень» с запретом записи снизу, и изолированный Pilot (средний уровень) не может открыть его на запись, хотя права по списку у него есть. Так выглядела ошибка «Отказано в доступе по пути …\Downloads\….zip».

## Редакция myAdmin

- Pilot-myAdmin ставится и запускается как клиенты: `Pilot-myAdmin-setup_<версия>.zip` лежит в `/release/` и `/beta/`, те же листинг, распаковка, отдельный профиль и установка в систему. Буква в имени учётной записи `M` (`plabcdM26x13x62219`), её знает и проверка имён в повышенной копии.
- Имена не угаданы, они прочитаны с установленного 26.13: `Ascon.Pilot.MyAdmin.exe`, `ProductName` и название в «Программах и компонентах» «Pilot-myAdmin», ключ `HKLM\SOFTWARE\ASCON\Pilot-myAdmin` с `InstallPath` и `Version`, данные в `%LOCALAPPDATA%\ASCON\Pilot-myAdmin` (там есть `Update`, как у клиентов, поэтому предупреждение про обновление в панели версии остаётся).
- Внутри установщика два MSI (32 и 64 бита) с `ProductName` «Pilot-myAdmin» и `ALLUSERS=1`; действий с драйвером виртуального диска в них нет, поэтому диалог «Установить в систему» для myAdmin не говорит о драйвере. При установке MSI завершает `Ascon.Pilot.MyAdmin.exe` и `Ascon.Pilot.Updater.Service.exe`.
- Заметки: строки «Pilot-myAdmin Desktop» и (выпуски 2024 года) «Pilot-myAdmin»; «Pilot-myAdmin Web» это другой продукт и пропускается.
- Блока «Расширения» для myAdmin нет (`Edition.SupportsExtensions = false`): папки `Development` в его профиле нет, PilotLookUp и DynamoPilot рассчитаны на клиент Pilot. Не проверено, грузит ли myAdmin расширения вообще.

## Избранные версии

- Кнопка-звезда справа от выбора версии (подсказка «Добавить в избранное» / «Убрать из избранного»). Избранные версии выбранной редакции идут в начале списка (между собой от новых к старым), остальные как раньше; в списке и в строке выбора у них золотая звезда.
- Хранятся в `settings.json`, поле `Favorites`: строки `<EditionId> <версия>` (`IceEnterprise 26.4.0.60408`), одна версия может быть избранной независимо в каждой редакции. Сохранение сразу при нажатии; при ошибке записи изменение откатывается и показывается ошибка. Список избранного один для обычного и предварительного режима.
- Версия для сравнения в заметках по умолчанию это следующая старшая (`VersionLibrary.ComparisonPartner`), а не соседняя в списке: порядок списка с избранными больше не «от новых к старым». Выбранная пользователем версия для сравнения не сбрасывается при обновлении списка.

## Установка версии

- Список версий разбирается из HTML-листинга (nginx autoindex) и кэшируется на диске для работы без связи.
- Установщики Pilot это WiX Burn с контейнером CAB; сервер отдаёт файлы по диапазонам байтов. Лаунчер читает контейнер, вынимает MSI и распаковывает его административным образом (`msiexec /a`) без установки в систему.
- Место на диске: пик установки считается как три размера zip плюс 256 МБ, проверка до начала. Для сохранения zip в папку проверяется размер файла плюс 64 МБ.
- В панели версии, которая запускается в отдельном профиле (или готова к распаковке), показан текст: «Если Pilot предложит обновиться, откажитесь: обновление ставится службой PilotUpdater в систему и может заменить установленную там версию». Запись в `Update` профиля не блокируется.

## Работа без интернета

- Редакция и версия файла: для имени вида `Pilot-<редакция>-setup_<версия>.zip|exe` берутся из имени. Иначе для exe (и для zip: для exe внутри него, он на время вынимается в `.tmp`) из ресурса версии: `ProductName` сопоставляется с `Edition.MsiProductNames` (для ICE Enterprise 26.9: «Pilot-ICE Enterprise», `FileVersion` 26.9.0.61368), версия из `FileVersion`. Если определить нельзя, окно спрашивает редакцию и версию.
- Исходный файл пользователя не удаляется и не копируется: exe читается на месте, из zip вынимается копия в `.tmp`, и удаляются только промежуточные файлы оттуда. В манифест версия записывается как `LocalFile`.
- «Добавить из файла...» (меню «Файл», выбор нескольких файлов) и перетаскивание файлов на окно: файлы ставятся по очереди, непригодный файл не останавливает остальные, итоговый список причин показывается в плашке ошибки.
- Настройка «Папка с установщиками»: при каждой перезагрузке списка папка (без вложенных) сканируется на `Pilot-*-setup_*.zip|exe`, найденные версии получают источник `LocalSetup` в `VersionEntry` и помечены «из файла, без сети». Если есть и exe, и zip одной версии, берётся exe. Для такой версии «Запустить» распаковывает файл и запускает, даже если версия есть в каталоге. Недоступная папка даёт плашку, а не ошибку запуска.
- «Скачать для офлайна...»: zip выбранной версии скачивается в выбранную папку как есть (через `.part`, с докачкой по Range и прогрессом), без распаковки. Существующий файл не перезаписывается.
- При отсутствии каталога (нет сети и нет сохранённого списка) установленные, системные и офлайн-версии продолжают работать. Список установленных показывается до ответа сети.

## Заголовок окна

## Заметки о выпуске

- Источник: статическая страница MadCap Flare (673 КБ), у неё нет `ETag` и `Last-Modified`, `robots.txt` разрешает всё. Разметка одинакова у всех 31 выпусков с 24.1.0.49302 по 26.13.0.62219: `<h2>Версия X.Y.Z.B от ДД.ММ.ГГГГ</h2>`, затем таблицы. Строка таблицы: ячейка с `<p class="CellBody">` (название продукта) и ячейка со списком `<ul><li>`; таблица с одной ячейкой (`class="warning"`) это предупреждение выпуска. Строка «Исправлены ошибки» есть в каждом выпуске, её пункты начинаются с «Продукт: текст».
- Разбор (`Core/Notes/ReleaseNotesParser`) без HTML-библиотеки, регулярными выражениями по известной структуре. HTML-комментарии (в том числе закомментированная таблица перед первым выпуском) вырезаются; в ячейке названия бывают пустой абзац `&#160;` и примечание («альфа-версия»), названием считается первый непустой абзац; вложенные списки двух видов (`<li>текст<ul>...</ul></li>` и выпуски 2024 года `<li>Pilot-BIM Desktop:</li><ul>...</ul>` с подсписком рядом с пунктом): первые становятся строками «- ...» внутри пункта, вторые назначают пунктам продукт. Названия продуктов в префиксах набраны вручную («Pilot_ICE Desktop», «Pilot-BIM-Desktop», «Pilto-ICE Web»), поэтому сравниваются по ключу: регистр, пробелы, `_` и `-` не различаются.
- Сопоставление редакций (`Core/Notes/EditionNotes`): ICE Enterprise, ICE и ECM читают «Pilot-ICE Desktop» и «Pilot-ICE», BIM читает «Pilot-BIM Desktop» и «Pilot-BIM», myAdmin читает «Pilot-myAdmin Desktop» и «Pilot-myAdmin» (так в выпусках 2024 года, где настольная и веб-редакции не разделены). Пункты строки без названия продукта берутся целиком, с названием другого продукта (подсписок «Pilot-ICE Web:») пропускаются. Исправления без продукта (выпуски 24.1-24.7, 24.12, 24.16) не приписываются никому, показывается их число.
- Предупреждения выпуска («Внимание! ...») показываются целиком, без привязки к редакции. Исправления в разделе «Что нового» свёрнуты: их бывает до 80 на выпуск.
- Версии: в заметках и каталоге версии совпадают точно в 30 случаях из 31 (24.40: 24.40.0.52162 против 24.40.0.51967). Если точного совпадения нет, берётся единственный выпуск с теми же первыми тремя числами, затем двумя; при нескольких кандидатах заметок нет. Режим «между версиями» берёт выпуски строго после старшей из границ в заметках и до младшей включительно; границу, которой нет на странице, берёт как есть.
- Кэш: страница хранится в `release-notes.html` в папке данных лаунчера, считается свежей сутки (по времени записи файла), потом скачивается заново. Недоступность сервера или страница без выпусков при наличии копии даёт старую копию и предупреждение с причиной (как у `ReleaseCatalog`); без копии это ошибка, раздел пишет, что заметок нет. Копия без единого выпуска считается отсутствующей. Загрузка идёт после списка версий и не задерживает его.
- Сертификат: сайт отдаёт сертификат Минцифры (Russian Trusted Root CA), которому Windows не доверяет без установки корневого сертификата. Кнопка «Установить» под предупреждением включает доверие этому корню только внутри лаунчера и только для help.pilotems.com; в Windows ничего не устанавливается, включение можно отменить.
- Тесты (`NotesTests`) работают на усечённой копии настоящей страницы `Fixtures/release-notes.sample.html`: девять выпусков, лишние строки таблиц и большинство исправлений убраны, остальное не тронуто.

## Установка в систему

Выбранная версия ставится настоящим установщиком с заменой установленной. Пакет MSI (проверено на ICE Enterprise 26.9.0.61368) ставится на всю машину (`ALLUSERS=1`, нужен администратор), запускает `pfm-ascon.exe install` (драйвер Pismo) и `dsp.exe 0` (политика подписи драйверов); один UpgradeCode на все версии, `RemoveExistingProducts` в последовательности 1401, поэтому обновление вверх проходит штатно; понижение запрещено условием запуска `NOT WIX_DOWNGRADE_DETECTED`.

- Действие выбирается по версии установленного клиента той же редакции (`SystemClientPlan.Choose`): нет клиента - установка; цель новее - обновление установщиком; цель старше - сначала удаление установленного, потом установка; та же версия - отказ (пункт меню недоступен).
- Установленная версия определяется как в `SystemInstallDetector`: `HKLM\SOFTWARE\ASCON\<продукт>\InstallPath` и версия exe. Список «Программы и компоненты» для этого не используется: в нём бывают устаревшие записи.
- Запись для удаления подбирается по точному совпадению названия продукта редакции и версии (`ClientUninstallLocator`). Бандл в `Package Cache` предпочтительнее голого MSI. Строка из реестра не исполняется: принимаются только `"<Package Cache>\{guid}\Pilot-<редакция>-setup.exe" /uninstall` и `MsiExec.exe /X{guid}`, команда собирается заново (`/uninstall /quiet /norestart /log ...` или `msiexec /x {guid} /qn /norestart /l*v ...`). Pilot-Server, BIM Server и записи других редакций выбраны быть не могут.
- Удаление из системы (пункт меню «Удалить из системы...», `SystemInstaller.UninstallAsync`): доступно, когда версия установлена в системе, и независимо от копии лаунчера (при «система + копия» пункты «Удалить копию...» и «Удалить из системы...» работают каждый со своей половиной). Перед окном подтверждения проверяется, что клиент редакции не запущен; в подтверждении сказано, что копия лаунчера останется. Повышенная копия получает команду `uninstall-client --edition <имя> --version <четыре числа>` и сама находит запись об удалении тем же `ClientUninstallLocator`, что и при понижении; версия в команде должна совпасть с установленной сейчас, иначе отказ (чтобы не удалить 26.14, поставленную после того, как в окне видели 26.13). Тихий режим, коды 0, 1641, 3010 считаются успехом, журнал `system-uninstall-<редакция>-<версия>.log`. После удаления лаунчер проверяет, что клиент в системе больше не находится. Если записи об удалении нет, остаётся сообщение «удалите вручную».
- Повышение прав тем же механизмом (`--admin` через `runas`), одна команда `replace-client` (или `uninstall-client`) на всю операцию, один запрос UAC. Ограничители по образцу проверки имён учётных записей: редакция только из перечисления `EditionId` (имя, не число), версия из четырёх чисел, путь установщика только `<данные лаунчера>\system-setup\<32 hex>\<префикс установщика редакции>.exe` в нормализованном виде. Что установлено и какую запись удалять, повышенная копия определяет сама, а не получает от вызывающего.
- Установщик не хранится: скачивается заново (или берётся из файла пользователя и копируется в `system-setup`, исходный файл не трогается) и удаляется сразу после установки; старые остатки (старше 12 часов) убираются при следующем запуске операции.
- Если клиент этой редакции запущен (процесс по имени exe, любой пользователь), операция не начинается. Проверка до диалога и ещё раз перед установкой.
- Тихий режим `/quiet /norestart`; коды 0, 1641 и 3010 считаются успехом. После установки версия проверяется ещё раз по exe; если её нет, это ошибка. Журналы: `system-install-<редакция>-<версия>.log` и `system-uninstall-...` в папке журналов лаунчера, путь попадает в сообщение об ошибке.
- Отмена работает до запуска установщика; после этого операция доводится до конца, чтобы не оставить систему с наполовину удалённым клиентом.
- Источник установщика: центр загрузок (по `ReleaseEntry`) или файл (`SetupSource.LocalFile`, zip или exe). Для скачанной версии без записи в центре загрузок (нет связи и нет кэша) пункт недоступен.

## Расширения

Источник релизов: GitHub (`mahach666/PilotLookUp`, `mahach666/DynamoPilot`). Расширение ставится в `Development` конкретной версии.

- **Как Pilot находит расширения:** подпапки `%LOCALAPPDATA%\ASCON\<продукт>\Development\<имя>`, внутри файлы `*.ext2.dll` (загрузчик знает также `.ext.dll`, `.servext.dll`, `.webext.dll`, `extension.config.json`). Для `Pilot-ICE Enterprise` и `Pilot-BIM` это подтверждено; имена папок для ICE и ECM выведены по аналогии (`Edition.RegistryName`).
- **Общая копия через junction.** Релиз распаковывается один раз в `<папка версий>\.extensions\<id>\<тег>\<папка>`, версии ссылаются на него junction-ом. Он создаётся без прав администратора. Проверено на живом клиенте Pilot-ICE Enterprise 26.11: расширение-проба, лежавшее за junction в `Development`, загрузилось, а путь загрузки в сборке шёл через `Development`. Оба расширения пишут только во временную папку и в `%LOCALAPPDATA%\DynamoPilot`, не рядом со своими файлами, поэтому общая папка только для чтения им подходит.
- **Отдельный профиль.** Профиль версии (пользователь Windows) закрыт для запущенного лаунчера, поэтому его `Development` связывается один раз со своей папкой в хранилище (`.profiles\<пользователь>\Development`) повышенной копией лаунчера (`--admin link-development`): профиль создаётся при необходимости (`CreateProfile`), существующее содержимое переносится в общую папку, пользователю даются права на изменение. Команда принимает только учётные записи лаунчера, известные продукты и одну фиксированную цель. Перед удалением профиля повышенная копия снимает эти ссылки (`delete-user`), а `Directory.Delete(recursive)` в .NET на junction падает, поэтому для таких деревьев используется своё удаление (`Junction.DeleteTree`).
- **Кто что поставил.** Состояние расширений определяется по самим ссылкам: junction в хранилище лаунчера считается «нашим», всё остальное (настоящая папка, ссылка в другое место) чужим и без подтверждения не трогается; «Заменить» переносит чужую папку в `_replaced` и ничего не удаляет.
- **Обновление и удаление.** Обновление перевешивает ссылку на новый релиз, старый удаляется, когда на него не осталось ссылок (список ссылок `refs` рядом с релизом, ключ ссылки это пользователь отдельного профиля или `sys-<владелец>-<редакция>`). Если файлы старого релиза заняты работающим Pilot, он остаётся до следующего раза.
- **Проверка целостности.** SHA-256 из поля `digest` ассета GitHub; без него (старые релизы) проверки нет. Архив без папки верхнего уровня кладётся в папку расширения, а с папкой другого имени отклоняется.
- **Запросы к GitHub.** Без токена, лимит 60 в час на адрес; ответ хранится с ETag и считается свежим 6 часов, «не изменилось» (304) лимит не расходует. При сбое показывается сохранённый ответ с причиной.

## Обновление лаунчера

- При запуске, если в настройках включено «Проверять обновления лаунчера при запуске» (`CheckUpdates`, по умолчанию да, в том числе для старых файлов настроек), лаунчер спрашивает последний релиз `mahach666/PilotLauncher` тем же клиентом GitHub, что и для расширений (ETag, сохранённый ответ `extension-launcher.json`). Сборка из папки разработки (не одиночный exe) не проверяет. Ошибка проверки только пишется в журнал.
- Новее ли релиз: тег из трёх чисел сравнивается с версией сборки по первым трём (`LauncherUpdater.IsNewer`); тег, который не версия, обновлением не считается.
- Кнопка «Проверить сейчас» в настройках (раздел «Обновления») проверяет по требованию, независимо от галочки и без перезапуска: результат пишется рядом («Установлена последняя версия: X», «Доступна версия X. В главном окне появилась плашка «Обновить»», «Не удалось проверить: …», в сборке для разработки «Это сборка для разработки: она не обновляется сама»). Найденное обновление показывает плашку в главном окне, в том числе скрытую ранее кнопкой «Позже». Версия установленного лаунчера написана бледным шрифтом в левом нижнем углу окна настроек. Проверено в окне на трёх сборках: 1.3.5 нашла 1.4.0 и показала плашку, 1.4.0 ответила «последняя версия», сборка для разработки отказалась.
- Плашка «Доступна новая версия ... (у вас ...)» с кнопками «Обновить» и «Позже» и текстом релиза (раздел CHANGELOG) под «Что нового». Пока запущены клиенты Pilot, кнопка недоступна: перезапущенный лаунчер не знал бы их окон и перестал бы подписывать версии.
- «Обновить» скачивает `PilotLauncher-Setup.exe` (это тот же exe, что и в портативном zip) в `<exe>.new` рядом с запущенным (с докачкой), сверяет размер и SHA-256 из поля `digest` релиза; без контрольной суммы обновление не ставится. Затем запущенный exe переименовывается в `<exe>.old` (Windows разрешает переименовать работающий exe, но не перезаписать), новый получает его имя, запускается, а старый закрывается. Если новый файл поставить не удалось, текущий возвращается на место.
- Новый экземпляр удаляет `<exe>.old` (до 10 попыток раз в секунду, пока старый закрывается; если файл занят дольше, он остаётся до следующего запуска) и для установленной копии записывает новую версию в «Приложения» (`DisplayVersion`).
- Работает одинаково для установленной (`%LOCALAPPDATA%\Programs\PilotLauncher`) и портативной копии; если в папку портативной копии нельзя писать, показывается ошибка со ссылкой на страницу релизов.
- Обновление между двумя настоящими релизами (20.10.2026): скачанный из релиза GitHub портативный 1.2.0 предложил 1.3.0, за 6 секунд скачал `PilotLauncher-Setup.exe`, SHA-256 нового exe совпал с `digest` релиза, лаунчер перезапустился из той же папки версией 1.3.0 без плашки, новый экземпляр удалил `.old`.
- Проверено вживую (сборки 1.0.9 и 1.2.0 из текущего кода, обновление до настоящей v1.1.0 с GitHub):
  - портативная копия: найдена v1.1.0, скачана, сумма совпала, exe заменён, лаунчер перезапустился в 1.1.0;
  - установленная копия (`--install`): то же, перезапуск из `%LOCALAPPDATA%\Programs\PilotLauncher`; следующая версия при старте удалила `.old` и записала свою версию в «Приложения»; `--uninstall` после этого не оставил папки, ярлыка и записи;
  - галочка в окне настроек: выключение сохраняется, после перезапуска плашки нет; включение сразу проверяет и показывает плашку;
  - запущенный клиент (ICE Enterprise 26.13 из лаунчера): «Обновить» недоступна, показано объяснение; после закрытия клиента кнопка снова доступна;
  - папка портативной копии без права создавать файлы: ошибка «Нет права записи в папку ..., обновите вручную» со ссылкой на релизы, exe не тронут, лишних файлов нет.

## Автообновление клиента

Клиент скачивает MSI в `%LOCALAPPDATA%\ASCON\<продукт>\Update\tmp` и просит службу PilotUpdater (LocalSystem, `net.pipe://localhost/PilotUpdater/WindowsService`, `StartClientUpdate`) поставить его на весь ПК. Для изолированного профиля эта цепочка по устройству клиента приводит к замене системной версии; на сервере другой версии это не проверялось, поэтому в тексте предупреждения «может заменить».

## Что проверено

- Центр загрузок отдаёт страницу листинга; в ней для ICE (с 15.0), ICE Enterprise (с 15.0), BIM (с 20.3), ECM (с 17.0) есть файлы `<Продукт>-setup_<версия>.zip` до 26.13.0.62219. Безымянные «latest»-файлы и серверные пакеты игнорируются.
- 8 установщиков (самый старый и самый новый каждой редакции) это одинаковый WiX Burn с контейнером CAB; сервер отдаёт файлы по диапазонам байтов.
- Распаковка ICE Enterprise 26.9.0.61368 и 25.12.0.57162 на локальных установщиках проходит целиком, клиент получается рабочий (интеграционные тесты). Клиент 26.11 запускался из обычной копии папки. Распаковка из zip на диске (после определения по имени) и из exe: исходный файл не меняется, в `.tmp` ничего не остаётся. Распознавание exe и безымянного zip по ресурсу версии (ICE Enterprise 26.9).
- Два клиента разных версий, запущенные рядом, открываются одновременно.
- Запуск установленного клиента через лаунчер: заголовок окна получает `[26.11.0.61894]`, лаунчер завершается вместе с клиентом.
- Заметки: разбор усечённой копии страницы и проверка на всей странице (31 выпуск, у каждого есть исправления, 23 исправления без продукта в выпусках 2024 года); раздел «Что нового» в окне в обоих режимах, предупреждение при недоступности сайта. Загрузка с живого сайта после «Установить»: заметки загрузились.
- Установка и удаление самого лаунчера (`-Setup.exe`, `--uninstall`) проходят, следов не остаётся. Ограничители `--admin` отказываются работать с чужими учётными записями.
- Расширения: на живом клиенте проверена загрузка расширения через junction. В окне блок «Расширения» показан для установленной версии: папки PilotLookUp и DynamoPilot.App, уже лежащие в `Development` пользователя, определены как «создана не лаунчером» и не тронуты.
- myAdmin вживую (портативная сборка): пятая редакция в списке, 160 версий из центра загрузок, установленная 26.13 определена «установлена в системе», блока расширений нет, у ICE Enterprise он есть; заметки 26.13 и 26.9 показывают пункты «Pilot-myAdmin Desktop», для 15.0.61 «в заметках нет версии»; запуск установленного myAdmin: процесс из `C:\Program Files\ASCON\Pilot-myAdmin`, заголовок окна `Pilot-myAdmin [26.13.0.62219]`. Настоящий установщик 26.13 (116 МБ) прошёл весь конвейер: скачивание, вынимание MSI, распаковка, поиск `Ascon.Pilot.MyAdmin.exe` (app 39 МБ).
- Размер окна вживую (портативная сборка): первый запуск 1100 на 780, после изменения до 1300 на 900 и закрытия настройки записаны и после перезапуска окно ровно такого размера, развёрнутое окно запоминается развёрнутым и при сворачивании возвращается к 1300 на 900.
- Избранное вживую: звезда поднимает версию наверх и помечает её, выбор не сбивается, две избранные идут от новых к старым, настройка сохраняется и читается после перезапуска, у другой редакции список не меняется; для 26.11 при избранных наверху сравнение идёт с 26.9, а не с соседом по списку.
- Меню версии вживую: для «система + копия» включены оба пункта удаления, для версии без установки и копии оба выключены, для версии только в системе (myAdmin) включено только «Удалить из системы...»; окно подтверждения показывается с нужным текстом, запрос повышенной копии без «Да» не уходит.
- 334 автоматических теста (из них 14 на доверие сертификату, 39 на расширения, 12 на удаление из системы, 9 на удаление копии, 11 на размер окна, 10 на доступ к данным копии и 37 на общие папки, в том числе на ссылки выше по пути: без новой проверки два из них падают): ядро, заметки о выпуске, работа без интернета, установка в систему (55, на подменённых реестре и запуске программ) и интеграционные на реальных установщиках (пропускаются, если файлов нет).

## Не проверено

- Общие папки, кроме папки по умолчанию: создание локальной группы, добавление в неё изолированных пользователей и выдача ей прав на выбранную папку через настоящий запрос Windows (повышенная копия) вживую не запускались, нужен администратор у экрана. Проверено тестами на подменённых группах и учётных записях с настоящими списками прав временных папок. Не подтверждено: что права группы действительно доходят до пользователя, уже вошедшего раньше (для работающего Pilot может понадобиться перезапуск версии), и что `ensure-user` в реальной системе добавляет только что созданного пользователя в группу.
- Удаление из системы целиком: настоящий деинсталлятор через «Удалить из системы...» не запускался (это удалило бы рабочий клиент). Логика проверена тестами на подменённых реестре и запуске программ; не подтверждено, что `msiexec /x` или бандл `/uninstall /quiet` отрабатывают без остатков и без перезагрузки, как и для понижения версии.
- myAdmin: запуск в отдельном профиле (нужен UAC) и установка в систему с заменой текущей не выполнялись. Распаковка настоящего 26.13 в папку и запуск установленного myAdmin 26.13 из лаунчера (метка версии в заголовке окна) проверены.
- **Установка в систему целиком.** Реальный запуск `setup.exe`, `msiexec /x` и бандла `/uninstall` в систему не выполнялся (тесты используют подменённые реестр и запуск процессов). Не подтверждено: что `/log` у Burn пишет журналы MSI рядом с указанным файлом; что `/quiet` не требует перезагрузки (коды 1641/3010 считаются успехом, перезагрузку лаунчер не запрашивает); что после удаления через бандл и через MSI повторная установка проходит без остатков; что обновление вверх реально проходит через `RemoveExistingProducts`; что у новых установок есть и запись бандла, и MSI одновременно (в этом случае берётся бандл).
- Сравнение версий: установщик, возможно, сравнивает только первые три поля версии MSI. Лаунчер сравнивает четыре; при равных трёх первых и разных четвёртых полях поведение пакета не проверялось.
- Создание пользователя Windows, запуск клиента под ним, удаление пользователя и профиля: требуют прав администратора и запроса UAC, в автоматическом прогоне не выполнялись.
- Метка версии в заголовке окна клиента, запущенного под другим пользователем Windows (для системного клиента проверена; для чужого процесса работает тот же `WM_SETTEXT`, но окно другого пользователя не пробовали).
- Скачивание реального zip с pilot.ascon.ru целиком (проверены только запросы диапазонов и весь конвейер на локальном установщике, завёрнутом в zip). Докачка и прогресс проверены на подставном сервере с Range.
- Распаковка установщиков ICE, BIM, ECM и старых версий (15.x-25.x): заголовки совпадают, содержимое MSI не смотрели. Имена exe и ключей реестра для ICE и ECM выведены по аналогии. Сопоставление `ProductName` с редакциями ICE, BIM, ECM проверено только на ICE Enterprise; безымянный exe других редакций может не определиться, тогда окно спросит.
- Поведение клиента при одновременном запуске двух версий в изолированных профилях (общий драйвер виртуального диска, единственный экземпляр).
- Загрузка заметок на ПК, где корневой сертификат Минцифры установлен в Windows (кнопка «Установить» там не нужна).
- Автообновление клиента при подключении к серверу другой версии: замена системной версии не воспроизводилась.
- Диалог выбора файлов, перетаскивание на окно, диалог «Какая это версия?» и выбор папки для zip руками не нажимались.
- Обновление лаунчера через прокси. Обновление установленной копии (не портативной) между двумя настоящими релизами: на них проверена портативная.
- Расширения: связывание профиля отдельной версии (повышенная копия, `CreateProfile`, права пользователю), скачивание настоящего релиза с GitHub через лаунчер и обновление до нового релиза на живом ПК. Совместимость релиза расширения с конкретной версией Pilot не известна и не проверяется.

## Риски и ограничения

- Длинный путь к папке версий: на настоящем установщике myAdmin `msiexec /a` завершился кодом 1619 («пакет не удалось открыть») при рабочей папке с путём около 190 символов и отработал при коротком `C:\tmp\...`. Причина по-видимому в длине пути; для стандартной папки `C:\ProgramData\PilotLauncher\versions` это не проявляется, для длинной папки версий из настроек возможно.
- Корневой сертификат Минцифры встроен в лаунчер и сверен только с корнем, который отдаёт сам сайт (совпал побайтово); источник: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt. Независимой публикации отпечатков не найдено. Доверие действует только для help.pilotems.com, включается с подтверждением и показом отпечатка, отключается. Отзыв сертификата не проверяется. Если Минцифры выпустит новый корень (в источниках упомянут ГОСТ-корень 2025 года), цепочка перестанет вести к встроенному корню, и файл придётся обновить.
- Смена разметки страницы заметок: разбор рассчитан на структуру выпусков 24.1-26.13; при странице без единого выпуска копия не затирается, при частичных изменениях разбор может пропустить пункты без ошибки.
- Обновление лаунчера доверяет GitHub: файл и его контрольная сумма приходят из одного релиза, подписи у exe нет. Защищает от повреждения и подмены по дороге, но не от того, кто получил доступ к репозиторию.
- Установка в систему меняет компьютер целиком (драйвер, политика подписи). Подпись и контрольная сумма скачанного установщика не проверяются.
- Повышенная копия принимает путь установщика из данных пользователя; от подмены между проверкой и запуском защищает только то, что папка принадлежит этому пользователю, а запрос UAC подтверждается им же.
- `msiexec /a` может потребовать повышения прав для некоторых MSI; тогда появится сообщение об ошибке, а не запрос UAC.
- При смене сервером формата листинга список версий сломается; кэш защищает от недоступности, но не от смены формата.
- Заголовок окна клиент может перезаписывать чаще раза в секунду; тогда на экране мелькнёт версия без суффикса.
