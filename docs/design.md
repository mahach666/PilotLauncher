# PilotLauncher: описание и принятые решения

Версия 1.0.0. Подробности и ограничения ниже; раздел «Не проверено» перечисляет то, что не проверялось на живом ПК.

## Зачем

Аналитики работают сразу с несколькими заказчиками, у каждого своя версия Pilot и тестовые базы. Сейчас клиент приходится переустанавливать при каждом переключении, а одновременно держать открытыми разные версии нельзя: установщик заменяет клиент на месте. Нужна программа в духе TLauncher: выбрать редакцию и версию, нажать «Запустить».

## Цели

- Скачивать версии ICE Enterprise, ICE, BIM, ECM из центра загрузок <https://pilot.ascon.ru/release/> и запускать несколько версий одновременно.
- Версии не мешают друг другу: свои настройки, логины, кэш.
- Версию, установленную в системе, определять и предлагать как готовую, с возможностью поставить копию для отдельного пользователя.
- Не раздувать диск: скачанные установщики удаляются сразу после распаковки.
- Работать без интернета: добавлять установщики из файлов, держать папку с установщиками, сохранять zip версии для переноса на ПК без сети.
- Выпускать и установщик, и портативную версию.
- В заголовке окна запущенного клиента видна версия.
- Для выбранной версии показывать заметки о выпуске с <https://help.pilotems.com/ru/Content/RelNotes.htm> и что изменилось между двумя версиями.

## Не цели

- Серверные пакеты Pilot, подключения к базам, управление базами.
- Любые изменения уже установленного Pilot, кроме явной команды «Установить в систему (заменить текущую)» (см. решения).
- Автообновление самого лаунчера, ПК без прав администратора, не-Windows.
- Очистка кэша и показ размера профиля версии (нужен доступ к чужому профилю; отложено).

## Анти-цели

- Неконтролируемый рост диска.
- Пугающие формулировки («удалить пользователя»), тихие остатки профилей и пользователей.
- Любое вмешательство в установленный в системе Pilot без явной команды и подтверждения пользователя.

## Согласованные требования

- Окно как у TLauncher: внизу выбор редакции и версии, большая кнопка «Запустить» со стрелкой-меню (удалить, открыть папку, ярлык, поставить для отдельного пользователя).
- Стенды не привязаны к заказчикам, это просто версии.
- Изоляция через отдельных пользователей Windows (у аналитиков обычно есть права администратора, одновременная работа нужна). Проверено руками до разработки: два клиента разных версий открываются рядом.
- При удалении версии спросить, удалять ли данные версии; слово «пользователь» не показывать.
- Установщик и портативная версия.
- Заметки с help.pilotems.com: сайт отдаёт сертификат Минцифры, которому Windows не доверяет. Решение: кнопка «Установить» под предупреждением включает доверие корневому сертификату Минцифры только внутри лаунчера и только для этого сайта; в Windows ничего не устанавливается, включение можно отменить.

- Расширения PilotLookUp и DynamoPilot: ставить в `Development` конкретной версии, с одной общей копией на все версии, с удалением и обновлением при выходе нового релиза. Источник релизов: GitHub (`mahach666/PilotLookUp`, `mahach666/DynamoPilot`).
## Заметки о выпуске

- Источник: статическая страница MadCap Flare (673 КБ), у неё нет `ETag` и `Last-Modified`, `robots.txt` разрешает всё. Разметка одинакова у всех 31 выпусков с 24.1.0.49302 по 26.13.0.62219: `<h2>Версия X.Y.Z.B от ДД.ММ.ГГГГ</h2>`, затем таблицы. Строка таблицы: ячейка с `<p class="CellBody">` (название продукта) и ячейка со списком `<ul><li>`; таблица с одной ячейкой (`class="warning"`) это предупреждение выпуска. Строка «Исправлены ошибки» есть в каждом выпуске, её пункты начинаются с «Продукт: текст».
- Разбор (`Core/Notes/ReleaseNotesParser`) без HTML-библиотеки, регулярными выражениями по известной структуре. Учтено то, что есть на странице: HTML-комментарии (в том числе закомментированная таблица перед первым выпуском) вырезаются; в ячейке названия бывают пустой абзац `&#160;` и примечание («альфа-версия»), названием считается первый непустой абзац; вложенные списки двух видов (`<li>текст<ul>...</ul></li>` и выпуски 2024 года `<li>Pilot-BIM Desktop:</li><ul>...</ul>` с подсписком рядом с пунктом): первые становятся строками «- ...» внутри пункта, вторые назначают пунктам продукт. Названия продуктов в префиксах набраны вручную («Pilot_ICE Desktop», «Pilot-BIM-Desktop», «Pilto-ICE Web»), поэтому сравниваются по ключу: регистр, пробелы, `_` и `-` не различаются.
- Сопоставление редакций (`Core/Notes/EditionNotes`): ICE Enterprise, ICE и ECM читают «Pilot-ICE Desktop» и «Pilot-ICE», BIM читает «Pilot-BIM Desktop» и «Pilot-BIM» (так в выпусках 2024 года, где настольная и веб-редакции не разделены). Пункты строки без названия продукта берутся целиком, с названием другого продукта (подсписок «Pilot-ICE Web:») пропускаются. Исправления без продукта (выпуски 24.1-24.7, 24.12, 24.16) не приписываются никому, показывается их число.
- Версии: в заметках и каталоге версии совпадают точно в 30 случаях из 31 (24.40: 24.40.0.52162 против 24.40.0.51967). Если точного совпадения нет, берётся единственный выпуск с теми же первыми тремя числами, затем двумя; при нескольких кандидатах заметок нет, а не угаданные. Режим «между версиями» берёт выпуски строго после старшей из границ в заметках и до младшей включительно; границу, которой нет на странице, берёт как есть.
- Кэш: страница хранится в `release-notes.html` в папке данных лаунчера, считается свежей сутки (по времени записи файла), потом скачивается заново. Недоступность сервера или страница без выпусков при наличии копии даёт старую копию и предупреждение с причиной (как у `ReleaseCatalog`); без копии это ошибка, раздел пишет, что заметок нет. Копия без единого выпуска считается отсутствующей. Загрузка идёт после списка версий и не задерживает его.
- Тесты (`NotesTests`) работают на усечённой копии настоящей страницы `Fixtures/release-notes.sample.html`: девять выпусков, лишние строки таблиц и большинство исправлений убраны, остальное не тронуто.

## Решения по реализации

- WPF, .NET 10, тема Fluent по настройке Windows. Один самодостаточный exe, .NET на ПК не нужен.
- Имя пользователя: `pl` + 4 символа хэша SID владельца + код редакции + `<мажор>x<минор>x<сборка>`, не длиннее 20 символов. Хэш владельца нужен, чтобы два аналитика на одном ПК не сбрасывали пароли друг друга.
- Пароль случайный, 32 символа, хранится через DPAPI для текущего пользователя Windows.
- Пользователи скрываются с экрана входа записью в `HKLM\...\Winlogon\SpecialAccounts\UserList`.
- Папка версий по умолчанию `%ProgramData%\PilotLauncher\versions`: у остальных пользователей там чтение и запуск, но не изменение чужих файлов (стандартные права ProgramData), отдельный ACL не нужен.
- Повышение прав через `runas` для той же программы с ключом `--admin`; помощник работает только с учётными записями своего формата (`^pl[0-9a-f]{4}[EIBC]...`).
- Установка лаунчера для одного пользователя: копия exe, ярлык «Пуск», запись в «Приложения». Установщик это тот же exe, у которого имя оканчивается на `-Setup`.
- Версии без интернета (по заданию, детали ниже):
  - Редакция и версия файла: для имени вида `Pilot-<редакция>-setup_<версия>.zip|exe` берутся из имени. Иначе для exe (и для zip: для exe внутри него, он на время вынимается в `.tmp`) - из ресурса версии: `ProductName` сопоставляется с `Edition.MsiProductNames` (для ICE Enterprise 26.9: «Pilot-ICE Enterprise», `FileVersion` 26.9.0.61368), версия - из `FileVersion`. Если определить нельзя, окно спрашивает редакцию и версию.
  - Исходный файл пользователя (может быть единственной копией на флешке) не удаляется и не копируется: exe читается на месте, из zip вынимается копия в `.tmp`, и удаляются только промежуточные файлы оттуда. В манифест версия записывается как `LocalFile`.
  - «Добавить из файла...» (меню «Файл», выбор нескольких файлов) и перетаскивание файлов на окно: файлы ставятся по очереди, непригодный файл не останавливает остальные, итоговый список причин показывается в плашке ошибки.
  - Настройка «Папка с установщиками»: при каждой перезагрузке списка папка (без вложенных) сканируется на `Pilot-*-setup_*.zip|exe`, найденные версии получают источник `LocalSetup` в `VersionEntry` и помечены «из файла, без сети». Если есть и exe, и zip одной версии, берётся exe. Для такой версии «Запустить» распаковывает файл и запускает, даже если версия есть в каталоге (интернет не нужен). Недоступная папка даёт плашку, а не ошибку запуска.
  - «Скачать для офлайна...»: zip выбранной версии скачивается в выбранную папку как есть (через `.part`, с докачкой по Range и прогрессом), без распаковки. Существующий файл не перезаписывается.
  - Плашка при отсутствии каталога (нет сети и нет сохранённого списка): установленные, системные и офлайн-версии продолжают работать. Список установленных показывается до ответа сети, а не после него.
- Заголовок окна (без названия редакции, она уже есть в заголовке Pilot): фоновый поток раз в секунду дописывает ` [версия]` к заголовку окон процесса клиента через `WM_SETTEXT`; лаунчер остаётся жить в трее, пока клиенты запущены.
- Предупреждения выпуска («Внимание! ...») показываются целиком, без привязки к редакции: среди них есть важные для всех (долгое обновление базы), и привязать их к продукту нечем.
- Исправления в разделе «Что нового» свёрнуты: их бывает до 80 на выпуск, а заметные нововведения короче.
- Список версий разбирается из HTML-листинга (nginx autoindex) и кэшируется на диске для работы без связи.
- Место на диске: пик установки считается как три размера zip плюс 256 МБ, проверка до начала. Для сохранения zip в папку проверяется размер файла плюс 64 МБ.
- Предупреждение об автообновлении: в панели версии, которая запускается в отдельном профиле (или готова к распаковке), показан текст: «Если Pilot предложит обновиться, откажитесь: обновление ставится службой PilotUpdater в систему и может заменить установленную там версию». Запрет записи в `Update` профиля не делается: неизвестно, откажется ли клиент подключаться без обновления.

## Установка в систему

Нужна обратная операция: поставить выбранную версию настоящим установщиком, заменив установленную. Основание, проверено на MSI ICE Enterprise 26.9.0.61368: пакет ставится на всю машину (`ALLUSERS=1`, нужен администратор), запускает `pfm-ascon.exe install` (драйвер Pismo) и `dsp.exe 0` (политика подписи драйверов); один UpgradeCode на все версии, `RemoveExistingProducts` в последовательности 1401, поэтому обновление вверх проходит штатно; понижение запрещено условием запуска `NOT WIX_DOWNGRADE_DETECTED`.

Решения:

- Выбор действия по версии установленного клиента той же редакции (`SystemClientPlan.Choose`): нет клиента - установка; цель новее - обновление установщиком; цель старше - сначала удаление установленного, потом установка; та же версия - отказ (пункт меню недоступен).
- Установленную версию берём как `SystemInstallDetector`: `HKLM\SOFTWARE\ASCON\<продукт>\InstallPath` и версия exe. Список «Программы и компоненты» для этого не годится: в нём бывают устаревшие записи (на этом ПК остаётся Pilot-ICE Enterprise 25.9 при реально установленной 26.11).
- Запись для удаления подбирается по точному совпадению названия продукта редакции и версии (`ClientUninstallLocator`). Бандл в `Package Cache` предпочтительнее голого MSI. Строка из реестра не исполняется: принимаются только `"<Package Cache>\{guid}\Pilot-<редакция>-setup.exe" /uninstall` и `MsiExec.exe /X{guid}`, команда собирается заново (`/uninstall /quiet /norestart /log ...` или `msiexec /x {guid} /qn /norestart /l*v ...`). Pilot-Server, myAdmin, BIM Server и клиенты других редакций не могут быть выбраны.
- Повышение прав тем же механизмом (`--admin` через `runas`), одна команда `replace-client` на всю операцию, один запрос UAC. Ограничители по образцу проверки имён учётных записей: редакция только из перечисления `EditionId` (имя, не число), версия из четырёх чисел, путь установщика только `<данные лаунчера>\system-setup\<32 hex>\<префикс установщика редакции>.exe` в нормализованном виде. Что установлено и какую запись удалять, повышенная копия определяет сама, а не получает от вызывающего.
- Установщик не хранится: скачивается заново (или берётся из файла пользователя и копируется в `system-setup`, исходный файл не трогается) и удаляется сразу после установки; старые остатки (старше 12 часов) убираются при следующем запуске операции.
- Если клиент этой редакции запущен (процесс по имени exe, любой пользователь), операция не начинается. Проверка до диалога и ещё раз перед установкой.
- Тихий режим `/quiet /norestart`; коды 0, 1641 и 3010 считаются успехом. После установки версия проверяется ещё раз по exe; если её нет, это ошибка. Журналы: `system-install-<редакция>-<версия>.log` и `system-uninstall-...` в папке журналов лаунчера, путь попадает в сообщение об ошибке.
- Отмена работает до запуска установщика; после этого операция доводится до конца, чтобы не оставить систему с наполовину удалённым клиентом.
- Источник установщика: центр загрузок (по `ReleaseEntry`) или файл (`SetupSource.LocalFile`, zip или exe). Для скачанной версии без записи в центре загрузок (нет связи и нет кэша) пункт недоступен.

## Расширения

- **Как Pilot находит расширения:** подпапки `%LOCALAPPDATA%\ASCON\<продукт>\Development\<имя>`, внутри файлы `*.ext2.dll` (загрузчик знает также `.ext.dll`, `.servext.dll`, `.webext.dll`, `extension.config.json`). У пользователя это `Pilot-ICE Enterprise` и `Pilot-BIM`; имена папок для ICE и ECM выведены по аналогии (`Edition.RegistryName`).
- **Общая копия через junction.** Релиз распаковывается один раз в `<папка версий>\.extensions\<id>\<тег>\<папка>`, версии ссылаются на него junction-ом. Он создаётся без прав администратора. Проверено на живом клиенте Pilot-ICE Enterprise 26.11: расширение-проба, лежавшее за junction в `Development`, загрузилось, а путь загрузки в сборке шёл через `Development`. Оба расширения пишут только во временную папку и в `%LOCALAPPDATA%\DynamoPilot`, не рядом со своими файлами, поэтому общая папка только для чтения им подходит.
- **Отдельный профиль.** Профиль версии (пользователь Windows) закрыт для запущенного лаунчера, поэтому его `Development` связывается один раз со своей папкой в хранилище (`.profiles\<пользователь>\Development`) повышенной копией лаунчера (`--admin link-development`): профиль создаётся при необходимости (`CreateProfile`), существующее содержимое переносится в общую папку, пользователю даются права на изменение. Команда принимает только учётные записи лаунчера, известные продукты и одну фиксированную цель. Перед удалением профиля повышенная копия снимает эти ссылки (`delete-user`), а `Directory.Delete(recursive)` в .NET на junction падает, поэтому в лаунчере для таких деревьев своё удаление (`Junction.DeleteTree`).
- **Кто что поставил.** Состояние расширений определяется по самим ссылкам: junction в хранилище лаунчера считается «нашим», всё остальное (настоящая папка, ссылка в другое место) чужим и без подтверждения не трогается; «Заменить» переносит чужую папку в `_replaced` и ничего не удаляет.
- **Обновление и удаление.** Обновление перевешивает ссылку на новый релиз, старый удаляется, когда на него не осталось ссылок (список ссылок `refs` рядом с релизом, ключ ссылки это пользователь отдельного профиля или `sys-<владелец>-<редакция>`). Если файлы старого релиза заняты работающим Pilot, он остаётся до следующего раза.
- **Проверка целостности.** SHA-256 из поля `digest` ассета GitHub; без него (старые релизы) проверки нет. Архив без папки верхнего уровня кладётся в папку расширения, а с папкой другого имени отклоняется.
- **Запросы к GitHub.** Без токена, лимит 60 в час на адрес; ответ хранится с ETag и считается свежим 6 часов, «не изменилось» (304) лимит не расходует. При сбое показывается сохранённый ответ с причиной.
## Что проверено

- Центр загрузок отдаёт страницу листинга; в ней для ICE (с 15.0), ICE Enterprise (с 15.0), BIM (с 20.3), ECM (с 17.0) есть файлы `<Продукт>-setup_<версия>.zip` до 26.13.0.62219. Безымянные «latest»-файлы и серверные пакеты игнорируются.
- 8 установщиков (самый старый и самый новый каждой редакции) - это одинаковый WiX Burn с контейнером CAB; сервер отдаёт файлы по диапазонам байтов.
- Распаковка ICE Enterprise 26.9.0.61368 и 25.12.0.57162 на локальных установщиках проходит целиком, клиент получается рабочий (интеграционные тесты). Клиент 26.11 запускался из обычной копии папки.
- Подмена `APPDATA` в окружении не изолирует версии: часть путей берётся из профиля через API Windows. Поэтому изоляция сделана пользователями Windows.
- Запуск установленного клиента через лаунчер: заголовок окна получает `[26.11.0.61894]`, лаунчер завершается вместе с клиентом.
- Заметки: разбор усечённой копии страницы и проверка на всей странице (31 выпуск, у каждого есть исправления, 23 исправления без продукта в выпусках 2024 года); раздел «Что нового» в окне в обоих режимах, предупреждение при недоступности сайта (окно со сменённым временем копии, сайт при этом отдаёт ошибку сертификата).
- Установка и удаление самого лаунчера (`-Setup.exe`, `--uninstall`) проходят, следов не остаётся. Ограничители `--admin` отказываются работать с чужими учётными записями.
- Распаковка ICE Enterprise 26.9.0.61368 и 25.12.0.57162 из zip на диске (после определения по имени) и из exe: исходный файл не меняется, в `.tmp` ничего не остаётся. Распознавание exe и безымянного zip по ресурсу версии (ICE Enterprise 26.9).
- 222 автоматических теста (из них 14 на доверие сертификату и 39 на расширения): ядро, заметки о выпуске, работа без интернета, установка в систему (43, на подменённых реестре и запуске программ) и интеграционные на реальных установщиках (пропускаются, если файлов нет).

- Расширения: 39 тестов (junction, раскладка zip, хранилище, релизы, установка, обновление, удаление, общая копия на две версии, чужие папки, команда администратора). На живом клиенте проверена загрузка расширения через junction. В окне блок «Расширения» показан для установленной версии: папки PilotLookUp и DynamoPilot.App, уже лежащие в `Development` пользователя, определены как «создана не лаунчером» и не тронуты.
## Автообновление клиента: что известно

- Клиент скачивает MSI в `%LOCALAPPDATA%\ASCON\<продукт>\Update\tmp` и просит службу PilotUpdater (LocalSystem, `net.pipe://localhost/PilotUpdater/WindowsService`, `StartClientUpdate`) поставить его на весь ПК.
- Для изолированного профиля эта цепочка по логике приведёт к замене системной версии. Это выведено из устройства клиента, на сервере другой версии не проверялось, поэтому в тексте «может заменить».

## Не проверено

- **Установка в систему целиком.** Реальный запуск `setup.exe`, `msiexec /x` и бандла `/uninstall` в систему не выполнялся (по условию задачи; тесты используют подменённые реестр и запуск процессов). Не подтверждено: что `/log` у Burn пишет журналы MSI рядом с указанным файлом; что `/quiet` не требует перезагрузки (коды 1641/3010 считаются успехом, перезагрузку лаунчер не запрашивает); что после удаления через бандл и через MSI повторная установка проходит без остатков; что обновление вверх реально проходит через `RemoveExistingProducts`; что у новых установок есть и запись бандла, и MSI одновременно (в этом случае берётся бандл).
- Сравнение версий: установщик, возможно, сравнивает только первые три поля версии MSI. Лаунчер сравнивает четыре; при равных трёх первых и разных четвёртых полях поведение пакета не проверялось.
- Создание пользователя Windows, запуск клиента под ним, удаление пользователя и профиля: требуют прав администратора и запроса UAC, в автоматическом прогоне не выполнялись.
- Метка версии в заголовке окна клиента, запущенного под другим пользователем Windows (для системного клиента проверена; для чужого процесса работает тот же `WM_SETTEXT`, но окно другого пользователя не пробовали).
- Скачивание реального zip с pilot.ascon.ru целиком (проверены только запросы диапазонов и весь конвейер на локальном установщике, завёрнутом в zip).
- Распаковка установщиков ICE, BIM, ECM и старых версий (15.x-25.x): заголовки совпадают, содержимое MSI не смотрели. Имена exe и ключей реестра для ICE и ECM выведены по аналогии.
- Поведение клиента при одновременном запуске двух версий (общий драйвер виртуального диска, единственный экземпляр): пользователь запускал две версии рядом, подробности не фиксировались.
- Загрузка заметок на ПК, где корневой сертификат Минцифры установлен в Windows: кнопка «Установить» там не нужна, этот путь не проверяли. Без установленного сертификата загрузка с живого сайта проверена: после «Установить» заметки загрузились (проверка в окне через автоматизацию интерфейса).
- Автообновление клиента при подключении к серверу другой версии (см. выше): замена системной версии не воспроизводилась.
- Диалог выбора файлов, перетаскивание на окно, диалог «Какая это версия?» и выбор папки для zip руками не нажимались (только запуск и просмотр содержимого окна через UI Automation).
- Сопоставление `ProductName` с редакциями ICE, BIM, ECM: проверено только на ICE Enterprise. Имя файла с версией выручает, но безымянный exe этих редакций может не определиться, тогда окно спросит.
- Скачивание zip в папку с реального сервера (докачка и прогресс проверены на подставном сервере с Range).

- Расширения: связывание профиля отдельной версии (повышенная копия, `CreateProfile`, права пользователю), скачивание настоящего релиза с GitHub через лаунчер и обновление до нового релиза на живом ПК не проверялись. Совместимость релиза расширения с конкретной версией Pilot не известна и не проверяется.
## Риски

- help.pilotems.com отдаёт сертификат Минцифры России (Russian Trusted Root CA), которому Windows не доверяет без установки корневого сертификата. Решение заказчика: доверять ему только внутри лаунчера (кнопка «Установить», сертификат не ставится в Windows), только для help.pilotems.com, с подтверждением и отпечатком, с возможностью отключить. Источник сертификата: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt; независимой публикации отпечатков Минцифрой или Госуслугами найти не удалось, поэтому встроенный файл сверен только с корнем, который отдаёт сам сайт (совпал побайтово). Отзыв сертификата не проверяется. Если Минцифры выпустит новый корень (в источниках упомянут ГОСТ-корень 2025 года), цепочка перестанет вести к встроенному корню, и встроенный файл придётся обновить.
- Смена разметки страницы заметок: разбор рассчитан на структуру выпусков 24.1-26.13; при странице без единого выпуска копия не затирается, при частичных изменениях разбор может пропустить пункты без ошибки.
- Установка в систему меняет компьютер аналитика целиком (драйвер, политика подписи). Подпись скачанного установщика не проверяется, целостность тоже (см. «возможное улучшение» с `gost_hash_report`).
- Повышенная копия принимает путь установщика из данных пользователя; от подмены между проверкой и запуском защищает только то, что папка принадлежит этому пользователю, а запрос UAC подтверждается им же.

- `msiexec /a` может потребовать повышения прав для некоторых MSI; тогда появится сообщение об ошибке, а не запрос UAC.
- При смене сервером формата листинга список версий сломается; кэш защищает от недоступности, но не от смены формата.
- Заголовок окна клиент может перезаписывать чаще раза в секунду; тогда на экране мелькнёт версия без суффикса.
